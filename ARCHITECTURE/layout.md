# 布局语义、几何约束与设计参照

> 主库 `layout.rs` / `geom.rs` 的契约，以及**与 R 端 `plot_grid` 逻辑的对齐情况**。
> 协议标签见 `tag-protocol.md`；告警见 `warnings.md`。

## 1. 布局语义（cowplot 式，2026-09-16 五项改造）

| 项 | 语义 | 落地状态 |
|---|---|---|
| `--width` / `--height` | `--width` 定尺度；**省略 `--height`（或写 `--height auto`，二者等义，大小写不敏感）** ⇒ 画布高由"各行自然高（分配宽 ÷ 该行 Σ纵横比）+ margin + gap"推出，**该值就是输出画布**（`viewBox` 与 PNG 像素同一尺寸） | **已对齐 R**（用户明确要求"输入什么就输出什么"，不做"逻辑尺寸 ≠ 输出尺寸"的分裂） |
| `--rel-widths` / `--rel-heights` | 语义是"**乘在自然尺寸上的倍数**"（`1,1,2` ≡ `3.2,3.2,6.4`，只算比值）；**省略 `--rel-widths`** ⇒ 列宽按各输入 canvas 纵横比分配 ⇒ 每格宽高比 = 其画布宽高比 ⇒ **零变形**；**省略 `--rel-heights`** ⇒ 行高按各行自然高 | **已对齐 R**（`rep()` 式自动补齐**没做**，反而是 fail-closed，见下） |
| 字母空间 | 用 `--labels` 且**未显式给 `--plot-margin`** ⇒ 自动留字母带；显式给了则**尊重它**，并在字母会被裁时告警（W5） | **已对齐 R**（R 用外层 `ggdraw + plot.margin` 一次预留） |
| 空位/垫片 | `--input none` 占一个空格（R 的 `plot_grid(NULL, pp, NULL, rel_widths = c(0.08, 1-0.16, 0.08))` 等价物）；垫片的自然纵横比**按 1:1 计**，可用 `--rel-widths` 调 | **已有**（R 的 `NULL` 靠 `rel_widths` 定份额；这里没有天然尺寸，取正方） |
| `rel_*` 长度不符 | **fail-closed**：长度/取值非法直接报错 | **比 R 更严**（R 的 `rep()` 自动补齐；本项目原则是 fail-closed） |
| `--height` 与 `--rel-heights` 的关系 | **显式给 `--width/--height` 时完全正交**（画布你定，`rel_*` 只在矩形内重分配格子）；**省略 `--height`（auto）时** `--rel-heights` 还会决定推出的画布高（画布高 = Σ行高，行高 = 自然高 × 倍数） | 实现细节 |

**字母带与 margin 的耦合（与 R 的差异点）**：`--label-size auto` 是**画布宽的比例**、而 margin 是**常数**
⇒ 改 `--width` 就要**重算 margin**：默认 24 在 `W = 1200` 时会直接把字母裁掉（需 `margin.top ≥ ≈0.98 × 字号`）。
R 端不存在这条耦合（字号与 margin 同为 pt、随 dpi 同步缩放）。**规格化做法**：用 `--labels` 且**不显式给**
`--plot-margin`，让字母带自动预留。

**现状摘要**：`--width` 定尺度；省略 `--height` 即自动推出；省略 `--rel-*` 即自然尺寸；
显式给 `--height`/`--rel-*` 时保持旧的"填满画布"语义（**旧调用点不受影响，但把 `--rel-widths` 填成
纵横比的老写法语义已变**，见 §3）。

**归一化**：`--normalize-input-max-side N` 是**逐输入等比缩放**——把输入的**长边**缩到 N，
**几何、`font-size`、`stroke-width` 一起缩**（`style="..."` 里声明的长度、svglite 的 `textLength`
与 `font-size`（含 `px` 后缀）同样处理）。`N` 要填**该面板目标格的长边** `max(格宽, 格高)`
（这个数不用手算：`--plan` 对每个输入直接打印格子尺寸与「格长边」，见 §4 末）
（竖版面板若误填格宽，长边只缩到格宽 ⇒ 面板比格子小、`s ≠ 1` 并触发 W1）。**理由见 §4**。

## 2. 几何约束

- `geom::scale_panel_to_cell` 用 **`sx = cell.width / canvas.width`、`sy = cell.height / canvas.height`
  两轴独立**缩放，即把画布盒**拉伸铺满格子**（是变形，不是留白）。因此
  **格子宽高比必须与源画布宽高比一致**，否则面板变形。调用方通过
  `--width/--height/--ncol/--nrow/--rel-widths/--rel-heights` 配准
  （`available_w = W − margin.left − margin.right − gap·(ncol−1)`，`cell_w = available_w·relw_i/Σrelw`，行同理；
  默认 `margin = 24`、`gap = 0`）。
- **画布尺寸 = 输出栅格的像素数**（SVG 是矢量，画布尺寸不影响清晰度，只影响坐标与 PNG 像素数）。
- **PNG 的 dpi 是文件元数据（pHYs 块）**：`--png-dpi`（默认 600）只写元数据，不改像素数、不缩放坐标。
- `AlignMode` 目前在 `plot_grid()` 内**未被使用**（`main.rs` 恒传 `AlignMode::Panels`）。
  R 脚本全程不用 `align`，靠嵌套绕开 ⇒ 本版不做。
- **合成时面板内容不再被面板画布裁剪**：组图器把面板内容**内联**进 `<g data-svg-grid-cell=…>`，
  没有嵌套 `<svg>` 视口 ⇒ 超出面板画布的元素（实测：matplotlib panel 的 colorbar 标签在 panel 本地
  `x ≈ 4749 > 画布宽 4661`）在原栅格成品里被裁、在本管线里会**渲染到外边距**。密集版式下可能压到相邻面板；
  要严格复刻栅格语义需在 cell 上补 clip（**尚未做**）。
- **内嵌位图的清晰度 = "原生像素 → 格子像素"的倍率**：**倍率 > 1 就是放大糊**。要么让格子不小于原生像素，
  要么回渲染端按目标尺寸重出。

## 3. 一处破坏性变更（2026-09-16）

`--rel-widths`/`--rel-heights` 的语义由"各面板纵横比"改为 **cowplot 式"乘在自然尺寸上的倍数"**。
以前把 `--rel-widths` 手填成纵横比的调用方，结果会变（变成纵横比的平方关系）。
**本仓受影响调用点已枚举**：仅 `tests/s22_repro/compose_s22.py`（已改为**省略 `rel_*`**，重跑后六格
`sx = sy = 1.000000`，比改前更好——E 由 0.9524 变 1）与 `out/skilltest*/assemble.sh`（历史测试产物，已过期）；
其余仅文档提及。

## 4. 为什么面板必须按"目标格子尺寸"出图（协议不缩放 font-size 的必然要求）

协议**永不缩放 `font-size`**（`transform.rs` 只对 `stroke-width` 应用缩放因子），所以

> **组图后文字的相对大小 = 设计相对大小 ÷ `s`，`s = 格子尺寸 ÷ 面板画布尺寸`**

`s ≈ 1` 时文字比例与设计一致；`s` 明显大于 1（面板被放大）时文字**相对变小**——这是协议的设计
（保证不同面板字号一致），**不是渲染或标签出错**。S22 实测 `s = 4.8`（F 达 7.53）时文字相对只剩
13–21%，不可读。两条正规做法：
- **出图端按目标尺寸画**（`figsize` 与所有以 pt 为单位的尺寸同乘 `k = 目标格宽 ÷ 画布宽`）；
- 或**归一化到目标尺度**（`--normalize-input-max-side`，见 §1）。

**`k = s` 是唯一可证安全的档位**：matplotlib 面板的轴外元素（标题、y 轴标签、图例）是出图时按点烘死的，
放大超过 `s` 会被裁掉或压到刻度上。

**核对 `s` 的方法**：用**带 `data-scale` 标签**的元素坐标反解
（`sx = (out.x − out_panelbox.x) / (in.x − in_panelbox.x)`）。**不要**用 `data-panel-box` 那个 rect 判断
——它通常没有 `data-scale` 标签、默认策略是"只平移"，尺寸本来就不变（实测某次真实 `s` 是 0.860/0.803，
而按 rect 判会得出 1.0）。

**逐行归一化的代价**：逐行按各自格宽归一化（保证 `s = 1`）⇒ **不同行的纸面字号不同**
（S22 实测 5.85 / 3.96 / 9.10 pt）。要全图字号一致，只能放弃 `s = 1` 或让各行格宽一致。

**同行面板必须"同宽 + 同高"**：行内两格共享行高 ⇒ 纸面字号由 `格长边 ÷ 面板长边` 决定，两个面板不同高时
必然一个被放大、一个被缩小（实测同行 `2180×1500` 与 `2180×2500`：`1875/1500 = 1.25×` vs
`1875/2500 = 0.75×`，后者从 5.0 pt 掉到 3.75 pt）。

### 格子尺寸由工具算，不靠调用方手算（R26）

`sx/sy` 与每个 target cell 都是本模块内部的中间量（`compute_grid` + `geom::cell_scale`）。它们**不再是**
调用方要自己拿 `W/--ncol/--plot-margin` 反推的东西：`svg_grid plot-grid … --plan` 把「画布尺寸 / 每个输入
落进多大的格子 / 被缩放多少（`s`）/ 变形多少（`Δ`）」直接打出来，并给出该输入的下一步命令
（`ARCHITECTURE/cli.md` §`--plan` 是契约，输出格式只在那里定义）。

约束只有一条：**计划与真跑必须是同一次计算**。`plan_grid()` 与 `plot_grid()` 共用 `lib.rs::prepare()`
（读入 → `--normalize-input-max-side` → `compute_grid`），`sx/sy` 共用 `geom::cell_scale()`——所以"计划说
`cell=150x120, s=1.5`"与"成品里那个面板真被放大 1.5 倍"是同一句话，不是两次各算一遍的巧合
（`round-data/R26` 用真产出 SVG 的 `data-scale` 坐标反解校验过）。

## 5. 设计参照：R 端 `plot_grid` 的组图逻辑（本工具的设计初衷）

范本：`research/白藜芦醇胰腺癌/steps/01_bulk筛选_单细胞空转基础分析/results/scripts/plot_grid.R`
（677 行；编排全部来自 `cowplot::plot_grid`，脚本内无 `source()`）。
**判断"哪里该改"以该逻辑为准，而不是以 `svg_grid` 现状为准。**
（用户原话：*注意是逻辑*；*要是可以复刻出 cowplot 类似的组图逻辑，agent 用起来将会很丝滑，
就像我自己在 R 里使用一样，通常十多行代码就可以组好一张图*。）

**逻辑特点（"用起来丝滑"的具体机制）**

1. **组图期完全不谈尺寸**：全脚本没有任何 `plot_grid(..., width=, height=)`；`width/height` 只出现在最后
   落盘的 `png(width=, height=, res=)`（如 `png(..., width = 4000, height = 4000*(2^0.5), res = 300)`）。
   尺寸只影响输出分辨率，不影响组图对象本身。
2. **`rel_*` 只算比值**：上游 `x_deltas <- rel_widths/sum(rel_widths)`、`y_deltas <- rel_heights/sum(...)`；
   脚本里 `c(1,1)`、`c(1,0.8)`、`c(0.1,1)`（和≠1）随处可见 ⇒ `c(1,1,2)` ≡ `c(3.2,3.2,6.4)`；
   单值还会 `rep(..., length.out = rows/cols)` 自动铺开。
3. **面板在格内弹性重排**：格内文字/轴线/标题保持 pt 绝对量、panel 主体吃剩余空间（R grid 的 null 单位）
   ⇒ **调用方不需要知道任何面板的纵横比**；同排共用 `y_delta` 天然等高、同列共用 `x_delta` 天然等宽。
4. **嵌套天然成立**：一次 `plot_grid()` 的产物就是普通面板，可直接塞进上一层（脚本叠到 3 层）；
   每层 `rel_*` 只在本层归一化，层间无需任何配套数字。
5. **字母**：`"AUTO"` 自动编号（`LETTERS[1:num_plots]`）；位置写在"格内相对坐标"（`x + label_x*x_delta`）；
   某格不要字母写 `""`。
6. **留白不靠 margin 参数**：外层 `ggdraw() + theme(plot.margin = margin(t,r,b,l,unit="pt"))` 统一预留；
   要"两侧留白"就用 `NULL` 占位格。
7. **跨面板对齐不设参数**：脚本全程不用 `align`；需要对齐就先组子图再整体放入。

**调用方不需要手算的东西**：行列数（给一个另一个自动）、每格占比的分母、每格位置与尺寸、
面板纵横比与边距、画布宽高（只在保存时给一次）、字母编号与位置、"空位"。

**与 R 逻辑的对齐情况**（2026-09-16 起；逐条决策见 `../ARCHITECTURE.md` §已定型的决定）

| 要点 | R 端 | `svg_grid` 现状 |
|---|---|---|
| 画布宽高 | 后置/自动：只在保存时给 | **已对齐**：省略 `--height` ⇒ 画布高由各行自然高推出，且该值就是输出画布 |
| 面板纵横比 | 不需要喂 | **已对齐**：省略 `--rel-widths` ⇒ 列宽按各面板纵横比分配 ⇒ 零变形 |
| `rel_*` 语义 | 乘在自然尺寸上的倍数 | **已对齐**：`1,1,2` ≡ `3.2,3.2,6.4` |
| 字母空间 | 外层一次预留 | **已对齐（自动预留）**：见 §1 |
| 空位/垫片 | `NULL` + `rel_widths` | **已有**：`--input none` |
| `rel_*` 长度不符 | `rep()` 自动补齐 | **已改为 fail-closed**（比 R 更严，符合项目原则） |
| 文字条（标题/图注条） | `ggdraw() + draw_label()` + `rel_heights` 份额 | **未做**：主库只搬运 `<text>`、不生成文字 ⇒ 需先做成"只有文字的面板" |
| 跨面板对齐 | 不设参数，靠嵌套绕开 | 一致：`AlignMode` 仍未使用（本版不做） |
