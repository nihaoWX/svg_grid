# 非致命告警（fail-loud 的契约与清单）

> 主库 `src/warnings/`（R8 拆成目录：`mod / scale / labels / content / passthrough / tests`）。
> **文案的单一来源就是这些模块**——本文件只定"怎么写、怎么和下游配合"，不复制文案。

## 1. 契约

1. **每条回答三个问题**：*发生了什么* / *为什么重要* / **怎么办**。三条齐全才算写完一条告警
   （`src/warnings/mod.rs` 的模块文档把这条写成显式契约）。
2. **一次调用聚合一条**：同类 offender 合并成一条消息，按 `(输入, 元素, 属性, 细节)` **去重**，
   超过 `MAX_LISTED = 6` 折叠成 `+N more`（五十个同样畸形的 path 也只出一行）。
3. **非致命**：只写 stderr，**退出码不变、产物字节不变**（有测试锁定）。末尾另打一行固定的收尾句：
   `non-fatal warning(s) — the exit code and the output file are unchanged`。**这一行不带条数**
   （R25 起；条数就是上面的行数，`1 non-fatal warning(s)` 这种写法不再出现，见 §1.5 规则 3）。
4. **一律英文**（前缀 `svg_grid: warning:` / 原因前缀 `svg_grid: note:`）——本工具将来开源。
5. **只在真触发时出声**：正常路径**零字节 stderr**（`compose_s22.py` 全流程 stderr = 0 字节是回归项）。

## 1.5 文案规则（2026-11-06 R25 定，实测见 `round-data/R25/`）

1. **单条 ≤ 200 字符**（含 `svg_grid: warning: ` / `svg_grid: note: ` 前缀，用 `awk '{print length($0)}'`
   实量）。实现在 `src/warnings/mod.rs`：`MAX_LINE = 200`，各 `describe_*` 用 `fit` / `assemble`
   在"信息最多且仍放得下"的形态里取第一个（先丢派生量、再丢 offender 的细节，**`Fix:` 永不丢**）。
2. **公共原因只打一次**：同因多条的告警把"为什么"抽成**每次运行最多一行** `svg_grid: note: …`
   （`NOTE_FONT_SIZE` / `NOTE_CANVAS_INK` / `NOTE_INK_DUST` / `NOTE_PASSTHROUGH` /
   `NOTE_FONT_FALLBACK` / `NOTE_LABEL_CLIP` / `NOTE_DANGLING`），各条只留"是什么 + 哪个输入 + 怎么修"。
   **没有告警时 note 一行都不出现**（成功路径仍是 0 字节 stderr）；`doctor` 的 `classify` 只数
   `svg_grid: warning:` 行，所以 note 既不进 `warnings=N`、也不参与告警码判定。
3. **`N = 1` 不打计数**：`1 input` / `1 cell` / `1 attribute`，不写 `1 input(s)`；收尾句也不带条数。
   唯一例外是 **W9 的 `N reference(s) point at an id that …`**：`round-data/R16` 逐字断言
   `1 reference(s) point at an id that nothing in the output defines` 与 `2 reference(s)`，
   改成人话会让 R16 变红，故保留该括号形式（`src/warnings/refs.rs` 有注释、R25 的 `meta.toml` 有记录）。
   `round-data/R16` 另外还逐字要求收尾句含 `non-fatal warning(s)` 与
   `the exit code and the output file are unchanged`，因此收尾句保留这两个短语、只去掉条数。

**第 6 条（`convert --check` 的 `hint: source canvas is …`）的取舍**：它属于**报告行**、不是告警；
但本轮**仍把它压到 ≤ 200 字符**（实测 182 字符），于是"任何一行 stderr/stdout 都不超过 200"是一条
无例外的规则，不必再为报告行写豁免。


## 2. 判据取向

- **宁漏报不误报**（用户要求）：遇到不认识的东西（例如祖先 `<g transform>` 不在黑白名单里），
  `ink.rs` 的做法是**丢掉该元素自身的几何、继续递归它的子节点**，而不是猜一个位置报出来。
  `round-data` 的证据也按这条写（"干净输入 ⇒ 必须静默"与"真越界 ⇒ 必须出声"成对断言）。
- **该报就一律报，不按"会不会在成品上现形"筛选**（W6 明确如此）：`A1` 那种"整块在画布外、栅格导出
  已静默丢字"的情形也必须出声。
- **容差各有各的理由**（数值不是随手取的）：

| 容差 | 值 | 为什么是这个值 |
|---|---|---|
| W1 缩放偏差 | **0.5 %** | **刻意的**：外层拼装漏给 `--plot-margin 0` 时偏差只有 `(W−48)/W ≈ 0.97%`；用 1% 会**正好漏掉**这条告警存在的理由。S22 参考管线精确到 1e-4，不会误报 |
| W2 拉伸 | **1 %** | 超过 1% 的宽高比偏差才肉眼可见 |
| W6 越界 | **1 px** | `text`/`tspan` 的墨迹盒是**比例估算**（几何图元才是精确的），零点几 px 的过冲是估算噪声 |
| W6 "微尘"提示 | **2 px** | 只是**自报优先级**、**不改判据**：全部越界都 < 2 px 时在报文末尾加一句"通常被 margin 吸收、仅供参考"。1.5 px 的真越界**仍然报** |

## 3. 清单（ID 是稳定接口：账本、`round-data`、测试都引用它）

| # | 触发条件 | 要点 |
|---|---|---|
| W1 | 某输入被布局缩放 `\|sx−1\|` 或 `\|sy−1\|` **> 0.5%** | 协议不缩放 `font-size` ⇒ 该面板文字相对大小随之改变。修法：按目标格尺寸出图 / 归一化 / 外层补 `--plot-margin 0` |
| W2 | 某格宽高比与面板画布宽高比偏差 **> 1%** | 该格被非等比拉伸（面板变形、文字与几何脱钩）。修法：省略 `--rel-*` 让布局按面板纵横比分配 |
| W3 | 某输入已含 `data-svg-grid-label` 而本次又传了 `--labels` | 给组合图重复加字母 ⇒ 重号/串位。字母只加在"拥有该面板为直接输入"的那一层 |
| W4a | `--labels` 条目数与输入数不符 | 多余的被忽略、缺少的不标；跳过某格用空条目 `--labels A,,C` |
| W4b | `--labels` 里字母重复 | 同名面板无法区分 |
| W5 | 字母墨迹会越出画布 | 调大 `--plot-margin`（`top ≥ 字号`），或省略它让字母带自动预留 |
| W6 | 某输入的**内容墨迹越出它自己的画布**（2026-09-27 R4） | **一律报**。两种后果：① 该输入**自己的 PNG 会静默丢字**；② 组图时若该侧 margin 为正，越界部分**贴着成品边缘现形**（如半个字形）。修法：出图端留足画布，或让该侧 margin 小于越界量。判据是"越出输入自己的 canvas box"（`geom::find_canvas_box`），**不是**"渲染到画布外" |
| W7 | **有几何无法重写、已原样保留**（2026-09-28 R6）：畸形 `<path d>`、非有限数值（`nan`/`inf`） | 浏览器对此宽容 ⇒ **出声但不阻断**（`rc` 与产物字节不变）。报文点名输入/元素/属性与"已原样保留"。**"属性串根本不成形"（`rect x="abc"`）仍 fail-closed**，口径没被放宽到别处 |

**支撑集与 `transform.rs` 一致**：主库能搬运的图元 = W6 能量的图元。`text`/`tspan` 按比例估算，
几何图元精确。**`<defs>` 子树同样参与**（R5 起：`<use>` 引用的几何在 `(x,y)` 处实例化后计入；
未被引用的 defs 内容不参与）。**悬空 `<use href="#missing">` 不报**（它什么都没画）。

**上游还有一条转换器告警**（`svg_grid_convert`，与 W1–W7 无关）：CSS `<style>` 块不被解析。
它应当在报文里自带"要不要管、怎么判断"（块内只有 `stroke-linejoin`/`linecap` 这类装饰 ⇒ 无害；
出现长度/`font-size` 才是真的没重算）——**与 W1–W7 同一条契约**。

## 4. 与 skill 的配合契约（2026-09-28 R9 定）

**告警是分支，不是开局知识。** 指南（`docs/general-figure-guide/`）**不得**逐条罗列告警的含义与处理；
它只说一句"**跑完先读 stderr**"。因此：

1. **每条告警必须自足**——读完 stderr 就能知道"发生了什么、为什么、怎么改"，不依赖指南；
2. **新增/修改告警时，不得要求同时改指南**（改了不必，不改也不许出现"指南里才有修法"）；
3. 指南里只允许出现**与告警无关的、调用方自己必须做的事**（如 `Path.to_polygons(closed_only=False)`、
   `pdftocairo -x/-y/-W/-H` 对 `-svg` 失效、幂等看 PNG、CJK `.ttc` 注册）——这些不是告警分支，
   工具不会替你喊。

**理由**（用户 2026-09-28）：*警告这些内容是属于分支，不同情况下触发不一样，因此 agent 不需要开局就
知晓它们，这些分支内容蕴含在脚本里是最好的——只有当真的触发的时候脚本返回它们才是最好的。*
